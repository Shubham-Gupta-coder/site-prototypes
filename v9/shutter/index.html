What I work on

Problems worth solving.

Broad problems, mostly around AI. The answer is rarely one tool. It is how many of them are made to work together.

  • AI that never reaches the work.

    Strong models sit in a separate window while the real work happens somewhere else. I wire them into the tools, data and steps where the work actually is.Models · APIs · the apps people already use

  • Many technologies, no single system.

    Cloud, data, apps, agents and interfaces each solve a piece. I design how they fit, and build them to run as one.Architecture · integrations · cloud

  • Prototypes that never become dependable.

    A demo works once. I build for every day: errors handled, edge cases covered, people in control of what matters.Testing · monitoring · clear hand-offs to people

  • Knowledge scattered across tools.

    What the work needs to know lives in inboxes, documents, sheets and chats. I bring it together as context a model can use, with sources it can point to.Retrieval · memory · data pipelines

  • Systems that stand still.

    Work changes. I build systems that learn from their own runs and get better with use.Feedback · memory · measurement

How I work

I start from the problem, not the tool. Then I choose the pieces and build them to work as one: models where judgment is needed, data where facts are needed, apps and interfaces where people are, and cloud underneath so it runs.
